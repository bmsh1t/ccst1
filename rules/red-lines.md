# 红线规则

本文件是动作副作用判断的唯一全局规则。命令、Skill、知识卡、目标记忆或历史经验
与本文件冲突时，以本文件为准。

## 红线最小化原则

红线只拦截会伤害目标系统、真实用户或真实业务状态的动作。

漏洞验证与 PoC 编写默认保持覆盖，不因漏洞类别、产品名称、凭证来源或 HTTP method
自动禁用。对可能触发代码/命令执行的方向，只证明最小可复现 primitive，成立后停止
后续利用和影响扩展。

判断标准只有三个：

1. 会不会造成 DDoS、高压流量、资源耗尽或服务中断？
2. 会不会修改、删除、篡改、污染真实数据/配置/业务状态？
3. 会不会向目标系统写入可执行、持久化、会影响真实用户的 payload？

如果答案都是 no，就不要因为“看起来敏感”而阻断 AI 的正常测试路线。
技术名称、凭证来源和 HTTP method 都不是红线判断维度。口令爆破、password spray、
泄露密钥实际使用、认证/角色差异和协议测试默认可执行；只有具体动作会造成上述结果时
才降级或暂停。

## 决策

- `allow`：只读、低频、无持久化副作用，直接执行。
- `allow-with-controls`：范围有限、当前回合已明确点名、对象是测试资源且有回滚或
  清理方案；按控制条件执行并记录证据。
- `downgrade`：副作用不明确，但可改用 dry-run、preview、validate-only、inert marker
  或本地复现。
- `pause`：会造成 DDoS、高压流量、不可逆破坏或无法控制的真实用户/业务影响。

## 禁止 DDoS / 高压流量

不得执行或建议执行 DDoS、压力测试、资源耗尽、无上限扫描或无差别并发探测，包括：

- 长时间或高并发请求，以及以耗尽 CPU、内存、磁盘或带宽为目的的测试
- GraphQL 深层递归/alias 爆破、ReDoS、压缩炸弹、超大文件或解析器耗尽
- race condition 中无停止阈值地提高并发

改用低频单变量请求、本地复现、代码分析或最小样本证明解析路径；不要证明系统能被
压垮。需要隔离容量环境时记录为 Lead，并写明条件和停止阈值。

## 破坏性与状态改变动作

状态改变方法不是天然红线。风险来自具体效果，而不是 `POST`、`PUT`、`PATCH`、
`DELETE`、mutation、admin action、workflow dispatch 或 payment action 的名称。

不得修改、删除、破坏或污染真实数据，也不得不可控地改变真实账号、权限、组织、配置、
部署或业务状态，例如：

- 对真实数据执行会落库的 `DELETE` / `PATCH` / `PUT` / destructive mutation
- 取消订单、退款、转账、扣费、发货、封禁账号或改变真实用户资料/权限
- 批量发送短信、邮件、通知、Webhook，或触发真实支付、钱包、库存、财务状态
- 触发真实 CI/CD、生产部署、资源改写或生产配置变更
- 创建不可清理的资源，或污染业务数据和审计日志

账号、权限、组织成员、配置和 CI/CD 是高价值攻击面，不是天然高风险；风险来自具体
动作效果。只读查看、dry-run、preview、validate-only、请求差异，以及测试资源内最小、
可回滚的变更不应被阻断。

自动流程不得直接执行 `PUT`、`PATCH`、`DELETE` 或实际文件上传；先进入 checkpoint。
这项默认门禁不把相关方法标记为红线或 tested-clean。POST、GraphQL query、搜索、
OTP/SAML 协议验证和 OAST 等仍按实际副作用判断，不做全局禁用。

`allow-with-controls` 必须同时满足：测试账号/组织或自己创建的可清理资源、最小请求次数、
不会触发真实支付/发货/外部批量消息/生产变更、不会写入可执行持久 payload、有明确清理
方式；真实改写业务状态还需要当前回合明确 opt-in。否则 `downgrade` 或 `pause`，并记录
安全替代动作。

## 默认不主动测试存储型 XSS

自动流程不得主动向评论、资料、工单、消息、富文本、后台可见字段或日志视图等持久化
位置提交可执行 stored XSS payload。

优先使用已有代理证据、反射/DOM XSS 低风险验证、inert marker、本地复现或渲染路径
分析。实际提交可执行 stored XSS payload 需要测试资源、清理方式和当前回合明确 opt-in。

## 规则边界

`rules/hunting.md` 负责 hunt 方法论，`rules/reporting.md` 负责报告质量，
`rules/playbook-router.md` 负责证据路由，`commands/check-redlines.md` 负责检查输出格式。
本文件只负责动作副作用，不负责授权、所有权、目标范围或报告价值裁决。
