# 只读评审设计与后续集成提案

## 目标与边界

第一阶段产出证据关联和集成建议，不改变产品架构、Git 引用、暂存区或运行数据。
最终方案后的用户 `go` 已批准第二阶段：仅将本地 main 一次快进到固定审查 tip，其他边界不变。
`research/refs.json` 记录机器可复核引用事实；`research/findings.md` 记录源码、历史验收、风险及建议。
不新建 registry、验证框架或长期维护的分支编排器。Git 操作与验证由主会话直接完成。

## 事实流与 owner

```text
已提交 Git 图 + 累计 diff + 已有规范/源码 + 历史验收
    → 区分本轮观察 / 历史运行 / 未证实事项
    → 分支矩阵、契约检查、风险分类
    → 用户审阅（任何集成操作的独立授权边界）
```

- Git 图决定是否已包含修复，不能由任务/分支名称决定合并顺序。
- `docs/architecture-contract.md` 决定 Store、raw、执行和派生投影边界。
- 历史测试记录只证明对应提交/环境；不汇总为当前 HEAD 的一次“全绿”。
- 当前两个用户暂存文件及其补丁以既有 `/tmp/fact-contract-baseline.vmDsm7/` 为保护基线，
  不用本轮生成的新基线掩盖差异。
- 任务的 `base_branch` 自动值不是集成目标授权；未刷新的 remote-tracking ref 不是实时远端事实。

## 集成方案取舍（已批准）

本地 main 是固定 tip 的祖先，因此一次 fast-forward 保留全部现有提交身份，成本最低。
逐分支 merge 会重复表达已包含关系；cherry-pick 会复制提交身份、增加遗漏和维护成本，均无必要。

获批后的操作放在 Git 原生独立 worktree，不改变当前分支/工作树/index。
它隔离 checkout 和未提交文件，但 refs/objects 仍共享；本次只批准移动 main 到约定 tip。
操作前固定起点和终点，拒绝任何不再满足的基线/祖先条件；只允许 `--ff-only`，无自动 rebase 或冲突解决。
不要求为纯引用快进重新运行已充分验收的产品测试；也不把引用检查说成最新完整发布验收。

## 兼容性与迁移

- Store schema 10 未变，不设计新数据库迁移。
- Surface cache schema 6→7；旧投影显式失效，使用现有刷新机制重建。
  快进代码不等于刷新用户目标，也不等于部署成功。
- Scanner/安装器保持 raw、claim 归属、用户配置和 explicit prune 的既有边界。
- 证据可携带性和 PR 回归门禁是后续维护建议，不在评审中顺手改动 CI 或强制追踪历史附件。

## 失败与回退

评审若发现引用、源字节或暂存补丁变化，停止并报告差异，不 reset/stash 或覆盖用户变化。
未来 `--ff-only` 若拒绝，保留原图并重新评审；若 worktree 已建立但后续失败，报告其路径和 refs 状态，
只在确认无用户改动时清理该临时 worktree，不盲目强制移除。
如果 main 已快进成功，不因后续清理失败自动回退 main。引用回退是另一个变更决策。
真实数据迁移/运行后的回退不属于本地 Git 集成；不能拿旧快照覆盖后续运行事实。
