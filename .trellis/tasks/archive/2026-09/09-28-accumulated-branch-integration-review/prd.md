# 累计分支集成审查

## Goal

只读核对累计提交的依赖、架构/恢复契约和已有验收，形成可复核、最低维护成本的集成建议。
优先保证架构与能力，其次考虑效率和维护成本；不重复已充分完成的验证。
用户审阅最终提案后回复 `go`，批准后续仅在隔离 worktree 中将本地 main 快进到固定审查 tip。
本地集成完成后，用户再次回复 `go`，批准提交并归档本任务记录；原暂存日志仍明确排除。

## Requirements

- R1：给出可复核的祖先链、重复分支/历史分支分类及最小集成顺序，不按名称猜测依赖。
- R2：重点核对唯一状态 owner、快照/恢复、执行锁与输入归属、安装边界，区分源码检查和历史验收证据。
- R3：列出真实阻断、待用户决策和非阻断限制；不为未知风险顺手改代码或重跑全量。
- R4：集成阶段保留原 HEAD、分支、产品工作区及旧日志字节/暂存状态；除 R5 所需的 Git/Trellis 元数据外，仅写本任务记录。
  收尾阶段仅允许当前分支新增本任务记录/归档提交，main 保持约定 tip；不切换分支、不 reset/stash、不带入旧暂存日志。
- R5：将本地 main 从 `0b00619f3975fdff3074d7f98007b57c7b39dc5c` 一次 `--ff-only` 快进到
  `857dc634828c5363842691dc58edacbdd81589c3`；仅在独立 worktree 中操作，拒绝基线漂移，验证后清理无改动的临时 worktree。

## Acceptance Criteria

- [x] AC1（R1）：提交/分支矩阵有精确 SHA、ahead/behind 和无共同祖先的明确处理；所有纳入分支可由 HEAD ancestry 解释。
- [x] AC2（R2）：关键边界对应源码/测试/验收记录；历史通过不冒充本次执行，CI 配置不冒充远端运行结果。
- [x] AC3（R3）：输出按风险分类的发现和推荐集成路径，目标分支与任何变更操作另行确认。
- [x] AC4（R4）：审查结束 HEAD/产品/旧暂存日志与基线不变，没有 merge/rebase/cherry-pick/fetch/push/部署。
- [x] AC5（R4/R5）：获批本地快进完成，main 与固定 tip 的 commit/tree 相同；原分支、HEAD、日志字节及暂存补丁保持原状，临时 worktree 已清理，没有新提交或远端/部署操作。
- [x] AC6（R4）：任务记录提交、归档并标为 completed，归档上下文引用可解析；两个提交不包含产品或旧暂存日志，main 和原日志保持不变。

AC1–AC4 记录只读阶段，AC5 记录本地集成阶段，AC6 记录另行批准的收尾阶段。对应证据见 `verification.md`。

## Technical Notes

- Store 数据库 schema 仍为 10；Surface 派生投影 schema 为 6→7，不能概括成“累计无 schema 变化”。
- 已有定向验收和较早发布基线只证明各自提交/环境；历史附件有部分仅保存在本机。
- 建议复用既有 CI job 补充持续回归门禁，不新建框架；这是后续建议，不是本任务修复范围。
- 集成及任务收尾分别获得明确批准；不扩展到 CI 修改、远端同步或其他任务归档。

## Out of Scope

产品修改、分支删除、真实目标/个人 runtime、未经确认的任何提交/集成动作、全仓测试、历史备用分支的批量合并和子代理。
远端刷新、推送、发布、安装和旧证据强制入库均不在本次授权内。
